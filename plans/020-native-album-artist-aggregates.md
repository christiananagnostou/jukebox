# Native album and artist aggregate foundation

## Status

DONE on branch `codex/020-native-library-aggregates`.

## Objective

Add bounded, revision-aware native album and artist summaries plus filtered track queries so secondary routes can stop loading the complete catalog at startup.

## Scope

1. Add typed aggregate query/page contracts capped at 100 rows.
2. Group artist and album summaries in the shared SQLx library boundary, using the existing FTS expression for search and an optional exact artist constraint for drill-down.
3. Return the catalog revision with every page so frontend pagers can reject mixed snapshots.
4. Extend track queries with exact artist/album filters for drill-down and user-triggered playback.
5. Add deterministic grouping, search, pagination, bounds, empty-metadata, and revision tests.
6. Extend the opt-in 100,000-track benchmark with first-page album and artist aggregate measurements.

## Non-goals

- No storage-tree migration; storage needs lazy path expansion and follows as a separate child layer.
- No route redesign or animation.
- No unbounded aggregate response.
- No removal of explicit single-file compatibility import.
- No playback playlist-descriptor migration in this backend slice.

## Safety and performance invariants

- User text is bound through SQL parameters and FTS syntax is generated by the existing bounded parser.
- Page size is clamped to 100 and offset is bounded to a valid non-negative integer.
- Artist and album pages have deterministic case-insensitive ordering with binary tie-breakers.
- Availability/search/filter semantics match the shared catalog query boundary.
- No source or fixture embeds a user's path or library data.

## Verification

- `cd src-tauri && cargo test --locked library`
- `cd src-tauri && cargo test --release --locked reference_100k_library_performance -- --ignored --nocapture`
- full Rust/frontend static, test, build, and application-bundle gates

The release benchmark passed against 100,000 deterministic tracks with artist first-page p95 at 49.1 ms and album first-page p95 at 93.0 ms. Both remain below the shared 100 ms query budget.

## Delivery

This backend contract is the base of a short stack. The album/artist frontend migration targets this branch; lazy storage traversal follows as its own independently buildable child.
